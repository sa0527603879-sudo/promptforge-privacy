# אינטגרציית smoove

שליחת מיילים דרך ה-API של smoove, בצד שרת בלבד.

## המפתח

המפתח נקרא ממשתנה הסביבה `SMOOVE_API_KEY` ומשום מקום אחר. הוא לא נשמר בקוד, לא
בקובץ ברפו, ולא מתקבל כארגומנט בשורת פקודה — ארגומנטים נשארים בהיסטוריית ה-shell
וגלויים ב-`ps` למשתמשים אחרים על המכונה.

**הרפו הזה ציבורי.** כל מה שנכנס לקובץ כאן גלוי לכל אחד, ונשאר בהיסטוריית git גם
אחרי מחיקה. `.env` נמצא ב-`.gitignore` וצריך להישאר שם.

### יצירת מפתח

בממשק של smoove: ריחוף על שם החשבון ← **API Keys & pixels** ← **Add API Key**
(או הגדרות ← API Keys).

בחלון היצירה יש בחירת רמת הרשאה. אל תיקח Full Permission כברירת מחדל — קח את
המינימום שהמשימה צריכה:

| רמה | למה היא מספיקה |
| --- | --- |
| Identification | הפעלת אוטומציה דרך API בלבד — מספיק ל-`trigger` |
| CRM Editing | יצירה ועדכון של אנשי קשר — מספיק ל-`subscribe` |
| Full Permission | הכול, כולל מחיקה. רק אם באמת אין ברירה |

אפשר גם להצמיד את המפתח לכתובת IP אחת. אם השליחה רצה משרת עם IP קבוע, זה שווה
את שתי הדקות.

### איפה שמים את הערך

לפי הסביבה שמריצה את הקוד:

- **Netlify** — Site configuration ← Environment variables
- **Supabase Edge Functions** — Function secrets
- **שרת משלכם** — מנגנון ה-secrets של הפלטפורמה
- **מקומית** — `cp smoove/.env.example .env` ומילוי הערך. הקובץ gitignored

## שימוש

```bash
# לוודא שהמפתח עובד. קריאה בלבד, בטוח להריץ תמיד
node smoove/cli.js verify

# הרשימות בחשבון, עם ה-id של כל אחת
node smoove/cli.js lists

# הוספה או עדכון של איש קשר ברשימה
node smoove/cli.js subscribe --list 123 --email dana@example.com --field firstName=דנה

# הפעלת אוטומציה עבור נמען אחד. בלי --yes זו הרצה יבשה
node smoove/cli.js trigger --automation 456 --email dana@example.com
node smoove/cli.js trigger --automation 456 --email dana@example.com --yes
```

`trigger` הוא הרצה יבשה כברירת מחדל ומדפיס מה הוא *היה* עושה. שליחת מייל בשם
הארגון היא פעולה שאי אפשר לבטל, ולכן היא דורשת `--yes` מפורש.

## איך שליחה עובדת ב-smoove

smoove היא מערכת אוטומציה שיווקית, לא ממסר מיילים. אי אפשר להעביר ל-API נושא וגוף
HTML ולבקש שישלח. התוכן נבנה ויושב בתוך smoove, ותפקיד ה-API הוא להגיד **למי**
ו**מתי**:

1. **שליחה מופעלת** — אוטומציה ב-smoove מוגדרת עם טריגר API. קריאה לטריגר עם איש
   קשר גורמת ל-smoove לשלוח לו את המייל שמוגדר באוטומציה. זה המסלול הטרנזקציוני:
   אישורי הרשמה, מיילי ברוכים הבאים, קישורי איפוס.
2. **שליחה לרשימה** — ניוזלטר שנבנה ב-smoove יוצא לרשימה. הוספת איש קשר לרשימה היא
   קריאת API; תזמון הניוזלטר עצמו נעשה בדרך כלל בממשק.

## מה עדיין צריך אימות

נתיב אחד בקוד לא אומת מול חשבון חי — `TRIGGER_PATH` ב-`send.js`, הנתיב להפעלת
אוטומציה. שאר הקוד בנוי סביב `client.request()` שמקבל כל נתיב, כך שאין כאן ניחושים
נוספים.

לאימות: בממשק, ליד ניהול מפתחות ה-API, יש אפשרות לבדוק את החיבור דרך Swagger. מצאו
שם את הפעולה של הפעלת אוטומציה, והשוו לנתיב בקוד. אם הוא שונה, אפשר לתקן בלי לגעת
בקוד — משתנה הסביבה `SMOOVE_TRIGGER_PATH` דורס אותו, עם `{automationId}` כתחליף.

אם הנתיב שגוי, `trigger` יחזיר שגיאה שמסבירה בדיוק את זה ולא 404 סתמי.

## פרטים טכניים

- `client.js` — אימות, טיפול בשגיאות, ניסיונות חוזרים על 429 ו-5xx עם backoff
  שמכבד `Retry-After`. המפתח לא נכנס לשום הודעת שגיאה
- `send.js` — פעולות השליחה
- `cli.js` — שורת הפקודה
- אין תלויות. Node 18 ומעלה, `fetch` מובנה
